> **產品定位**：無須登入、資料完全本機儲存的雙棲自適應記帳 PWA，專注於「3 秒快速記帳」、「精準多帳戶與信用卡週期模擬」以及「週期性固定收支與預算警示」。

---

## 1. 產品目標與核心價值

1. **隱私與即時可用（Local-first）**：開啟瀏覽器即可使用，不綁定雲端帳號、不依賴遠端伺服器，所有帳務資料儲存於使用者裝置的 IndexedDB。
2. **雙棲自適應體驗（Dual-Form UX）**：
   * **手機端（Mobile-first Quick Entry）**：針對單手操作最佳化，目標 **3 秒完成一筆消費輸入**。
   * **桌機端（Desktop Dashboard）**：提供高資訊密度的淨資產總覽、帳戶餘額卡片、信用卡各期帳單拆解、預算進度與快捷鍵操作。
3. **金融邏輯嚴謹性**：用完整的純函數帳務引擎與 Vitest 邊界測試解決一般簡易記帳軟體最容易出錯的場景（信用卡結帳日、分期餘數與跨月、轉帳重複計算、歷史改帳）。

## 3. 詳細功能規格與驗收標準（Acceptance Criteria）

### 3.1 多帳戶管理與淨資產計算
* **支援帳戶類型**：
  1. `cash`（現金）
  2. `bank`（銀行帳戶）
  3. `ewallet`（電子支付，如悠遊付、LINE Pay 餘額）
  4. `credit_card`（信用卡，含 `CreditCardConfig`）
* **淨資產公式**：
  * `總資產` = 所有未封存資產帳戶（`cash` / `bank` / `ewallet`）餘額與信用卡溢繳正餘額之總和。
  * `總負債` = 所有信用卡欠款（`-balance`，當 `balance < 0` 時）之總和。
  * `總淨資產` = `總資產 - 總負債`（等價於所有帳戶帶符號餘額之直接加總）。
* **驗收標準（AC）**：
  * [AC-ACC-01] 新增信用卡時，必須設定結帳日（`1–31`）、繳款日（`1–31`）與繳款月份偏移（同月 / 次月），並可選填信用額度。
  * [AC-ACC-02] 封存（Archive）已停用帳戶時，歷史交易必須完整保留不得刪除，且該帳戶可選擇是否計入淨資產或隱藏於日常快記選單。

### 3.2 交易紀錄與「3 秒快速記帳」流程
* **三種交易類型**：
  * **支出（Expense）**：扣減指定帳戶餘額，計入當月支出與對應分類預算。
  * **收入（Income）**：增加指定帳戶餘額，計入當月收入。
  * **轉帳（Transfer）**：從「轉出帳戶」扣款並等額加回「轉入帳戶」，**不計入收支報表與預算**。
* **快速記帳流程（Mobile Bottom Sheet / Desktop Modal）**：
  1. 預設焦點直接落在「金額輸入」與自訂計算機/數字鍵盤（手機不跳出系統混雜鍵盤，支援簡易 `+ / -` 試算）。
  2. 預設帶入「今日日期」與「最近一次使用帳戶」。
  3. 點選分類圖示（支援常用分類排序）後，可選擇直接儲存，或展開「備註 / 日期 / 分期開關」。
* **歷史改帳一致性**：
  * 修改或作廢（`void`）任意歷史交易（例如三個月前的消費或轉帳）後，所有受影響帳戶餘額、信用卡該期帳單金額與該月預算進度必須**即時重新計算且完全一致**。
* **驗收標準（AC）**：
  * [AC-TX-01] 金額輸入不允許 `<= 0` 或非法字元，底層儲存為整數 `MinorUnits`（無浮點誤差）。
  * [AC-TX-02] 轉帳的「轉出帳戶」與「轉入帳戶」不可為同一帳戶。
  * [AC-TX-03] 編輯歷史交易僅修改該筆紀錄，不會誤改其他交易；若屬分期子帳務，系統須明確提示「僅改單期」或「調整整筆分期計劃」。

### 3.3 信用卡週期模擬與一鍵繳款
* **帳期規則**：
  * **結帳日含當天**：若結帳日為 15 號，11 月帳單涵蓋 `10/16` 至 `11/15`；`11/16` 起算 12 月未出帳。
  * **月底自動對齊**：設定 29/30/31 號結帳或繳款時，遇小月或 2 月自動對齊該月最後一天（平年 `02-28`、閏年 `02-29`）。
* **信用卡明細頁需呈現四大指標**：
  1. **已出帳剩餘應繳（Remaining Statement Due）** + 距離繳款截止日倒數 / 逾期警示。
  2. **本期未出帳金額（Unbilled Spending）** + 距離下次結帳日倒數。
  3. **尚未到期分期總額（Future Installment Total）**。
  4. **可用額度進度條**（若有設定信用額度：`額度 - 總欠款 - 未到期分期`）。
* **一鍵繳卡費精靈**：
  * 在信用卡詳情頁點擊「繳卡費」，自動帶入：
    * 交易類型：`transfer`
    * 轉入帳戶：該信用卡
    * 預設金額：本期「已出帳剩餘應繳」金額（使用者可改為部分繳款或溢繳）
    * 使用者只需選擇扣款的銀行帳戶即可完成繳款，帳單狀態隨之更新為 `paid`（若全額繳清）。
* **驗收標準（AC）**：
  * [AC-CC-01] 全額繳清已出帳金額後，帳單狀態從 `open_due` / `overdue` 變為 `paid`，且未出帳金額不受影響。
  * [AC-CC-02] 若結帳後、繳款前產生溢繳，餘額正確顯示為正數（溢繳預存），剩餘應繳顯示為 `0`。

### 3.4 分期付款規則
* **建立分期**：
  * 選擇信用卡支出時可切換「分期付款」，輸入總金額與期數（如 `3, 6, 12, 24` 期或自訂）。
  * 預覽畫面即時顯示每期金額（標明首期或末期是否含除不盡餘數）與最後一期入帳月份。
* **展開與計算規則**：
  * 儲存時在單一資料庫 Transaction 內建立 1 筆 `InstallmentPlan` 與 `N` 筆子 `Transaction`（標記 `1/N` .. `N/N`）。
  * 日期以 `startDate` 的日（Anchor Day）為準逐月推移，遇二月縮減不影響三月回到原日期。
  * 未來期數（`transactionDate > 今日`）**不計入今日帳戶已發生負債與當月預算**，僅歸類於「未到期分期」；待月份到來自然併入對應帳期與預算。
* **異動規則**：
  * 支援「取消尚未入帳期數（提前結清 / 退貨）」，將未來子交易標記為 `void` 並保留過去已入帳紀錄。

### 3.5 週期性固定收支與啟動補發
* **規則設定**：支援 `daily`、`weekly`、`monthly`、`yearly` 及間隔（`interval >= 1`），可選填結束日期 `endDate` 與暫停開關 `isActive`。
* **無伺服器自動補發**：
  * 每次 App 啟動（以及使用者手動點擊「立即檢查週期項目」或頁面切換至跨日後），掃描所有 `isActive === true` 且 `nextRunDate <= 今日` 的規則。
  * 依規則補齊漏記日期之交易（含 `recurringRuleId + recurringOccurrenceDate` 冪等防重覆保護），並在 Dashboard 顯示「已自動補入 N 筆固定帳務」輕提示（Toast）。
* **驗收標準（AC）**：
  * [AC-RC-01] 連續重新整理頁面或同時開兩個分頁，絕不會產生重複的同日週期交易。
  * [AC-RC-02] 每月 31 號扣款規則經過 2 月（28 號產生）後，3 月仍準確在 `03-31` 產生。

### 3.6 分類預算與警示
* 支援「全月總支出預算」與「單一支出分類預算」。
* 支援設定每月預設金額，亦支援針對特定月份（如過年、雙 11）建立單月覆寫預算。
* **三段式狀態警示**：
  * `< alertThresholdPercent`（預設 80%）：正常（綠色）
  * `>= 80%` 且 `<= 100%`：接近上限（黃色警告）
  * `> 100%`：已超支（紅色警示並顯示超支金額）

### 3.7 JSON 資料備份與還原
* **匯出**：一鍵下載包含全部 6 張業務表資料與 `schemaVersion` 的 `.json` 檔案（檔名含日期戳記，如 `ledger-backup-2026-11-27.json`）。
* **匯入還原**：選擇 `.json` 後先執行結構驗證與外鍵完整性檢查；通過後提示「將覆蓋現有本機資料」，確認後於單一原子交易中完成還原。

## 5. 非功能性需求（NFR）

1. **資料精確度**：100% 整數運算，嚴禁金額出現 `.000000001` 誤差；Core Domain 模組單元測試覆蓋率目標 **>= 95%**。
2. **離線與效能**：PWA 離線可開啟與記帳；在累積 `10,000` 筆交易紀錄下，首頁淨資產與當月報表計算耗時應 `< 50ms`。
3. **跨環境相容性**：支援最新穩定版 Chrome / Edge / Safari（含 iOS Safari 加入主畫面 PWA 模式）。

## 6. Git 版本控制規範

本專案採用 Git 進行版本控制，規範如下：

1. **主分支保護策略**：
   * `main`：隨時保持可編譯、測試全數通過（`npm run typecheck && npm test && npm run build`）的穩定狀態。
   * 功能開發建議切出短週期分支，如 `feat/domain-credit-card`、`feat/ui-quick-entry`、`fix/installment-rounding`。
2. **Commit Message 格式（Conventional Commits）**：
   * `chore:` 專案設定、依賴、文件或建置腳本（例：`chore: initialize Vite + React + Dexie skeleton and specs`）
   * `feat:` 新功能（例：`feat(domain): implement credit card billing cycle engine`）
   * `fix:` 錯誤修正（例：`fix(domain): preserve anchor day across February leap years`）
   * `test:` 補充或調整測試（例：`test(domain): add boundary tests for installment remainder`）
   * `docs:` 文件更新
   * `refactor:` 不改變外部行為的重構
